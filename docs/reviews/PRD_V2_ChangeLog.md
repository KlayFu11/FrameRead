# FrameRead PRD V2 变更记录

日期：2026-11-15。本文是[现行 PRD](../prototype/PRD.md)与[PRD V2 草案](../prototype/PRD.v2.draft.md)的逐项对照记录，供评审使用。V2 只是需求文档版本，产品范围仍是完整 V1；已确认方向与四份 ADR 继续有效，新增业务细化、REQ/AT 和 S0–S12 的具体组织仍供本次评审，不代表功能已实现或运行验证。

本文只记录需求差异、保留项、验收关系和待由 SPEC 明确的问题，不修改现行 PRD、四份 ADR、`AGENTS.md` 或代码。当前原 PRD 的五维验收和 P1 三项仍是范围基线。

## 1. 变更判断口径

| 类型 | 本文含义 |
| --- | --- |
| 保留 | 原 PRD 承诺继续有效，V2 主要补充定位或验收证据。 |
| 增强 | 原承诺不变，补充边界、状态、失败结果或可执行验收。 |
| 新增 | 原 PRD 未形成独立、可核对的契约，V2 新增需求；仍须经过评审。 |
| 简化 | 删除或收窄非必要复杂度，不降低原有业务承诺。 |
| 延期 | 保留为后续方向，不作为完整 V1 或默认部署依赖。 |

优先级沿用 V2 草案：P0 是原有视频业务和正确性/可靠性/部署基础；P1 是备份恢复、内部运行概览、正式版本内容缓存实验；P2 是 MinIO/其他对象存储、Qdrant、Kubernetes 等额外技术。完整 V1 需要所有 P0 和三项 P1，P2 不阻塞 V1。

## 7. SQL 规则核对

当前 `AGENTS.md` 第 14 行原文如下，本轮建议原样沿用，不编辑 `AGENTS.md`：

> - SQL 查询优先保持简单，避免 N+1；是否使用关联或在代码中组装，应根据执行计划、查询次数、实际延迟和 I/O 判断，不设关联表数量上限。重要查询和修改需检查索引、扫描范围及实际开销，保留必要的测量证据。

理由是：避免 N+1 关注的是查询次数和整体延迟；是否关联两张或更多表不能脱离执行计划、扫描范围、索引、I/O 和代码组装成本判断。REQ-11、AT-20 和 AT-26 已把执行计划、查询次数、I/O/延迟和分页边界纳入证据，不应恢复固定“两表上限”。

## 8. 简化与延期说明

V2 的简化主要是整理原有契约、合并分散的身份与故障语义、拆成可独立验收的小切片，并把底层接口、状态机和实现细节留给 SPEC；这不删除可靠性约束，也不把任何原 V1 功能移出完整 V1。MinIO/其他对象存储、Qdrant、Kubernetes 等 P2 是额外技术方向，不是原 V1 承诺，也不是把原 V1 承诺延期，不能成为本地 Compose 验收依赖。

## 10. 当前评审结论

- V2 草案保留原 PRD 的完整 V1 业务范围；阶段一核心闭环及其他阶段切片都不等于完整 V1，完整 V1 还必须通过全部三项 P1 验收。
- P0 需求和 AT-01～AT-22、AT-26 构成主链与工程基础；REQ-15～17 和 AT-23～AT-25 是完整 V1 必验的 P1。

- 主动重新解读重新生成文章、失败 QA 显式新轮次、旧备份恢复时所有未完成任务结束为恢复中断失败且旧待投递/执行权失效，是待评审的业务细化，不是已批准的 ADR 变更。
- 所有实际运行、测试、性能和恢复结论都必须在对应 AT 中补充命令、环境、实际结果和脱敏证据；本文不能替代实现验收。
