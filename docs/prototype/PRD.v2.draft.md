## 1. 项目定位、使用者与交付范围

FrameRead 是以视频理解为业务场景、以后端工程交付为重点的个人 Web 应用。部署者提交 Bilibili 或 YouTube 单条视频链接，系统异步获取媒体、采用字幕或 ASR、读取真实画面、生成带时间出处的图文文章和全片导图，随后支持阅读、私人追问、导出和可撤销只读分享。

项目用于学习和展示 Python 后端、AI 应用服务化以及适量 React/TypeScript 全栈能力。验收关注业务完整性、架构合理性、工程正确性、运行可靠性和可复现性，不以读者是否学会视频知识作为工程验收标准，也不以研究通用 Agent 算法为目标。

| 使用者 | 能做的事 | 访问边界 |
| --- | --- | --- |
| 部署者 | 配置模型和 ASR、提交与管理任务、阅读与追问、导出、创建或撤销分享、维护实例 | 使用受信的个人管理入口；免登录不代表管理操作向公网匿名开放 |
| 分享访问者 | 阅读绑定版本的正式文章、全片导图和正式引用图片 | 仅凭有效分享链接访问上述内容，不能使用个人管理能力 |

保留 Python、FastAPI/Pydantic、PostgreSQL、SQLAlchemy/Alembic、Redis/Celery、FFmpeg/yt-dlp、React/TypeScript 和 Docker Compose 的主要方向。采用模块化单体与独立 Worker。LangGraph 仅用于单次文章任务内部的有界编排，不管理业务执行权、任务终态或正式发布。

参考版本为本地 [VidLens](../../reference-project/VidLens/) 和 [DoVideoAI](../../reference-project/DOVideo/) 代码，已有分析见[架构与实施依据](../research/FrameRead_Feasibility_Analysis.md)。本文规定 FrameRead 的行为，参考项目的实现不能替代本项目验收。

| 优先级 | 本文范围 | 完成口径 |
| --- | --- | --- |
| P0 | 原有视频业务，以及 API、数据库、事务、异步执行、并发与故障正确性、文件生命周期、资源限制、基础观测、测试、部署和一次实测优化 | 可以按切片交付可运行成果；全部 P0 验收通过才称为 P0 完成 |
| P1 | 配套备份恢复、内部运行概览、正式版本内容缓存实验 | 三项均属于完整 V1 验收；缓存实验必做，产品是否启用缓存由实测决定 |
| P2 | MinIO/其他对象存储适配、Qdrant 等独立向量库、Kubernetes 等额外部署平台 | 需另有业务收益与验收，不是 V1 运行依赖或默认开发任务 |

## 2. 从首次配置到使用成果

1. **本地启动与配置。** 部署者按说明使用 Compose 启动完整应用和依赖，完成迁移，保存可用图文模型与独立 ASR 配置。仅配置图文模型时，也能处理有可用字幕的视频。
2. **选择视频与解读方式。** 粘贴单条链接，选择模型、完整解读或关注点专题、深度及可选关注点。默认完整解读；两种模式都交付全片导图。
3. **找回或创建成果。** 相同视频和解读设置存在正式文章时，默认提供打开已有文章，展示标题、版本与生成时间。只有部署者选择重新解读，才受理新生成任务。首次处理则直接按接单规则受理。
4. **跟踪任务。** 受理后取得任务 ID，从历史、状态快照和 SSE 查看排队、阶段、草稿、错误与操作结果。刷新、断线或响应丢失后仍可找到原任务。
5. **阅读与核对。** 正式文章提供章节目录、时间出处、真实配图及全片导图；可查看原帧并回原平台核对。时间只能定位到区间时明确标示精度。
6. **私人追问。** 支持一般提问、选段提问和选帧提问，回答区分视频证据、文章解释、一般知识与外部资料。外部资料默认关闭，显式开启才检索与读取。
7. **导出与分享。** Markdown 和图文 ZIP 读取选定正式版本；分享链接固定版本、可撤销。追问与本地编辑的导出副本不回写正式文章。
8. **维护与恢复。** 在个人入口查看运行概览，按配置清理源媒体与临时文件，按文档备份恢复；正式成果及其长期证据保持可用。

## 3. 业务与工程需求

### REQ-01 配置与模型选择

P0。可保存多个模型配置，选择默认项，ASR 独立配置；密钥保存后脱敏回显，重启保留。模型连接或所需图文能力不可用时给出原因，不擅自换用其他模型。配置的连接与能力检查若需要真实调用，应由明确操作触发并记录，不因打开页面重复调用。

受理任务固定本次输入和模型、ASR、生成规则等语义配置；后来修改默认项不改变已受理任务。密钥轮换和语义配置变化分别处理，不能为恢复而长期保留失效明文密钥。仅保存配置不会自动启动或恢复视频处理。

没有可用字幕且未配置 ASR 时，已受理任务明确失败并提供设置入口。保存 ASR 后，可以从原任务页沿用链接和选项创建新任务，使用新配置；原失败任务保留，不要求重新填写输入。

### REQ-02 四类请求行为与身份关系

P0。下表区分四类请求行为；HTTP 操作、视频任务、正式文章版本、执行尝试和外部调用则是不同的可追溯对象。同一视频允许产生多个任务和正式版本，不能用视频 URL 的唯一性禁止主动重新解读，也不能把请求行为类型当成实体身份。

| 操作 | 用户可见结果与身份 | 历史保留与费用影响 |
| --- | --- | --- |
| HTTP 幂等重发 | 同一操作幂等键和相同请求返回原任务 ID；不因响应丢失、刷新或当前默认配置变化创建新任务 | 重发本身不增加生成调用；原任务仍可能正常继续执行和计费 |
| 历史结果匹配 | 按视频标识、解读设置及配置/生成规则版本查找已有正式成果；默认打开最近一次匹配版本 | 不创建生成任务、不调用模型；其他版本仍从历史可访问。匹配不能证明平台视频后来没有更新 |
| 主动重新解读 | 明确操作后创建新任务；成功发布新正式版本 | 可复用经验证仍有效的媒体/文本，文章生成重新执行，不能把旧文章冒充新生成；旧版本与旧分享不变，新任务可能产生费用 |
| 失败或取消后的主动重试 | 创建关联原任务的新任务，显示配置及可复用阶段；原任务不改回运行 | 仅复用输入、配置、来源和产物均有效的已完成阶段；新任务有新的期限与预算，新发送可能再次计费；原错误、草稿和 unknown 账不被覆盖或归零 |

同一幂等键携带不同请求时返回冲突，不修改原任务。已受理记录保留期间，幂等绑定不能因短期缓存失效而消失。视频提交、主动重新解读/重试、问答新轮次都须防止网络重发额外创建任务；问答重发返回原轮次和任务。键的格式与各操作的规范化规则留给 SPEC。

查找历史结果失败时说明查询失败，不能当作“没有匹配”而自动生成。自动恢复/安全重试在原任务内形成新执行尝试，不等同于部署者主动创建新任务。

### REQ-03 任务受理、执行与状态

P0。只有任务和待投递工作（Outbox）在 PostgreSQL 中一致持久化后，才返回 `202` 与可查询任务 ID。`202` 表示已受理，不表示媒体、模型或文章已完成。Redis/Celery 投递与执行信息不能成为任务最终状态的唯一依据。

执行槽占满时使用等待名额；等待容量也耗尽时，明确拒绝新任务并返回 `503`，不创建任务或待投递记录。并发接单遵守同一上限。符合访问与输入条件的已受理请求，使用相同幂等键和输入重发时，即使满额也返回原任务。见 [ADR 0004](../adr/0004-bound-video-task-admission.md)。

用户能区分排队、运行阶段、等待安全重试、取消已请求，以及成功、失败、已取消等结果。阶段、执行尝试和调用结果分别展示；unknown 是外部调用结果类别，不使本地任务无限处于运行中。执行权使用可失效、可续期的租约约束，失联后能够接管；阶段检查点（Checkpoint）只有持久化且仍有效，才被恢复流程认可。

必须满足以下不变量：

- 接单事务回滚时，不能留下单独任务、待投递工作或伪受理事件。提交结果暂时无法确认时，报告“受理结果未确认”，引导使用同一幂等键恢复，不能断言任务不存在。
- 已受理任务即使投递中断也能按原 ID 查询；投递恢复、重复消息和 Broker 数据丢失的修复不创建第二个业务任务。
- 只有有效执行者能提交阶段、草稿、资产和发布结果；接管后的过期 Worker 不能改写新结果或覆盖正式文件。
- 已完成阶段只有依赖和产物仍有效才可复用；同一任务内的自动恢复/安全重试不重置任务总期限、调用预算和失败历史。已成功、失败或取消的任务不能被补投改回运行，主动重试使用新任务。
- 排队任务可取消；运行中先持久确认取消请求，再确认已取消或已成功。确认请求后不再授权新阶段或外部调用，已获准并正在进行的发送仍可能完成或计费。取消与发布竞争必须有唯一裁决：取消先成立禁止发布，发布先完成保留正式版本。
- 同一任务最多发布一个正式文章版本，同一视频可经不同任务产生多个版本。正式版本、长期引用、任务成功结果与关键状态事件一致提交；发布失败不能留下对外可见的半成品正式版本，新版本不改旧版本、旧问答和旧分享。

关闭页面不取消任务。页面先取服务端快照，再续接 SSE；断线、缺口或游标过期时重新同步。旧事件不能让状态倒退，慢客户端不能造成无界内存占用，事件保留期限不影响任务当前状态的查询。

### REQ-04 来源、媒体和文件生命周期

P0。输入限 Bilibili 或 YouTube 单条视频，不要求部署者提供平台 Cookie。公开可取得的视频使用字幕优先、必要时 ASR 的路径；不支持、需要平台登录、受限、下载不完整或转写失败均明确报告，不承诺所有平台视频必然可取得。

来源快照代表本次实际取得的媒体与文本证据版本，不能只由 URL 判断。字幕/ASR 保留来源和可支持的时间精度；后续抓取或转写不能重写已被文章和问答引用的文本与时间关系。真实帧区分请求位置与实际取得位置，引用以实际画面为准。

| 数据 | 生命周期契约 |
| --- | --- |
| 正式文章、导图、字幕/转写、正式引用图片、私人问答及其引用证据 | 长期保留，重试、重新解读与源媒体清理不破坏既有引用 |
| 已完成阶段、草稿、执行与调用记录 | 保留恢复和排障所需的历史；未通过发布校验的草稿仅在个人入口查看 |
| 原视频、音频和临时工作区 | 按配置清理，先满足正在处理、读取、取帧和导出的保护条件 |
| 可重新构建的导出包 | 可以到期清理；从同一正式版本重新打包不调用模型 |

未完成、截断或校验失败的文件不能登记为可用正式资产。文件写入、登记与数据库发布之间发生崩溃时，必须可识别未完成产物或孤儿文件并安全处理。清理与新增引用/发布/导出并发时，不能删除已经受保护的资产；清理失败有记录且可继续收敛。

资源缺失或损坏时，阅读明确指出不可用资源，ZIP 导出失败；不能静默补造图片或自动重新生成文章。源媒体已清理后，现有文本和引用图片仍可用于阅读与追问；新画面需要重新取得媒体并验证同源及时间对应，无法验证时说明不能补看，已有证据保持原样。

### REQ-05 外部调用、unknown 与预算

P0。每次模型、收费 ASR 及其他受预算控制的外部发送都可关联任务、执行尝试、阶段和调用记录。发送前持久登记调用意图、输入证据并预留相应预算，发送后记录可获得的供应商请求标识、响应、错误、耗时和用量来源；记录不含凭据。

区分未发送、发送待确认、已确认成功、已确认失败和结果未知。收到响应但结构化内容不合格，是已收到响应后的业务校验失败，不能把已报告用量抹去；调用结果和用量是否已知分别记录，未知不能写成零。发送意图不等于供应商已收到或已计费，可能发送与已确认发送不能混为一谈。

调用意图已持久化而进程退出后，只有能够可靠证明确未发送，才可按安全重试规则继续；否则即使实际可能尚未发出，也按可能发送处理，不能因缺少完成记录就认定尚未调用。供应商无法查询结果且不保证幂等重发时，本地任务以失败结束，保留 unknown、预算记录、草稿和“上次请求可能已计费”的提示；队列重投、Worker 重启、SDK 重试和图恢复都不得隐式重发，也不能把未知用量归零后重用该预算。只有部署者主动重试才创建新任务及新发送。见 [ADR 0003](../adr/0003-retry-an-unconfirmed-model-call.md)。

供应商已经返回成功而本地回执尚未持久化时退出，同样属于恢复时无法确认的窗口。同一任务恢复时，若调用回执已经可靠保存、仅后续本地阶段尚未完成，可以复用该已确认响应继续校验，不再重发同一逻辑调用；无法确认的响应不适用此规则。

仅对可确认可安全重试的临时错误，在共享预算和期限内有限退避；错误参数、凭据和能力问题快速失败，不偷偷切换模型。各层重试不能相乘放大调用次数。内容修订受有界规则和同一预算约束，失败仍保留草稿。预算基于可确认用量、发送次数及保守预留，估算费用注明依据，不承诺仅靠本地记录精确封顶供应商账单。

### REQ-06 文章、证据、发布与阅读

P0。保留完整解读、关注点专题、深度和关注点。完整模式覆盖全片重要内容，关注点影响展开重点；专题模式明确覆盖和省略范围。全片导图独立于专题正文，节点能定位关联章节或原视频时间段，不能指向不存在的章节。

文章和问答默认简体中文，引用字幕/转写原句保留原语言与时间。正式正文可整理原片讲述、解释可见步骤，不能引入无原片依据的片外补充；相关解释留在私人问答。见 [ADR 0002](../adr/0002-keep-background-knowledge-in-qa.md)。

每个正式版本保存固定正文、导图及来源关系，章节和引用可回原片核对。发布前验证结构、引用归属、时间范围、原文和图片完整性；模型自称审查通过不能代替业务校验。缺少必要来源、视觉输入、章节或发布要求时，只保留未完成草稿，不能用限制说明掩盖缺失成果。

纯口播视频允许正式文章不引用截图，但真实画面仍须进入模型，说明未引用原因。画面读取失败不能冒充“口播无需截图”；教程仅在画面出现的步骤未经核实就不能写成已确认事实。内容不确定性明确展示，不宣称确定性校验等于语义绝对正确。

提供章节目录、全片导图、原帧查看和平台时间跳转。读者可在外部编辑器修改导出副本；站内正文、私人问答锚点和旧分享不改变，V1 不提供站内正文编辑或修订稿发布。

### REQ-07 私人追问

P0。支持直接提问、选中正式文章段落提问、针对实际帧提问。对话固定文章版本和来源；选段保留原文关联，选帧验证实际帧身份。新文章发布不自动替换旧对话上下文。

同一对话逐轮处理，上一轮未结束时不受理新的并发轮次并说明原因；网络重发返回原轮次/任务。失败或取消轮次保留，部署者可显式重新提问，形成关联原问题的新轮次和任务，基于已完成历史固定新上下文，不回插或覆盖后续回答。来源和配置变化须可见。

回答区分视频证据、文章解释、一般知识和外部资料。一般知识不挂原片时间；证据不足说明缺少什么。外部资料默认关闭，每轮是否允许使用可见；开启后保留实际读取的 URL、标题、读取时间与用于回答的原文证据，搜索摘要不能冒充已读原文。读取失败说明限制，不能伪造外部引用。

问答、引用证据和外部资料读取记录保留在个人实例，不回写正式文章、不随导出或分享公开。补看画面遵守 REQ-04，不以问答为入口隐式重新生成文章。

### REQ-08 Markdown 与图文 ZIP

P0。仅导出选定正式版本，包含正文、时间出处和全片导图，不包含私人问答。单个 Markdown 不是图片自包含文件，说明配图所依赖的资源与访问条件；导出不会自动创建公开分享。

ZIP 用相对路径打包正文和正式引用图片，解压后断网可读，导图也有不依赖远程渲染服务的可读表示；回原平台播放仍需联网。缺图、内容校验失败或构建中断时不交付伪完整包；纯口播无引用图片的正式文章可正常导出。重新打包、下载和读取不触发文章生成调用。

### REQ-09 只读分享

P0。部署者显式创建、查看和撤销分享链接。分享固定创建时选定的正式版本，后续重试、失败或新版本发布均不改变旧链接内容。见 [ADR 0001](../adr/0001-share-a-fixed-article-version.md)。

公开入口只返回绑定版本的正文、导图和正式引用图片，图片请求也校验分享有效性与允许范围。原始视频、音频、字幕、草稿、任务、配置、私人问答及未公开帧不在分享范围内；猜中其他任务或资产 ID 不获得访问权。

撤销确认后，新发起的页面、内容和图片请求均被拒绝，不能被静态资源地址、预先签发的其他资源链接或公开缓存绕过。此前已保存到访问者设备的副本无法收回；访问者需能连到部署者的分享入口，不提供代托管分享服务。

### REQ-10 管理访问与输入安全

P0。个人实例免注册登录，但个人入口默认仅供部署者按受信条件访问。开放分享入口不能同时开放配置、生成、取消、私人数据、备份和运行概览等管理能力。具体监听、鉴权、跨站写请求防护及代理信任方案由 SPEC 确定，必须有对应负验证。

分享访问者、任意公网请求、跨站写请求或伪造转发来源均不能越过管理边界。视频 URL、外部资料 URL、媒体地址和文件路径分别校验，不能访问实例任意文件或非预期网络目标；受信管理配置中的本地模型端点按独立规则处理。

密钥只通过受保护配置/专用密钥入口提供，普通 API、页面、日志、导出和公开资源不泄露凭据、内部异常栈或私人内容。文章、链接、图片和导出路径不能被内容输入利用来执行脚本或越界读写。

### REQ-11 API 与数据库质量

P0。API 错误提供稳定的机器可识别类别、用户说明、关联标识及可采取的动作。语义或参数不合法使用 `422`，幂等键内容冲突使用 `409`，接单满额使用 `503`，请求保护限流使用 `429`；异步业务失败保存在任务结果中。无效、撤销或越界分享资源返回一致的不可访问结果。详细 DTO、路径与完整状态码表留给 SPEC。

提供与实际行为一致、版本明确的接口说明，覆盖输入校验、错误及异步受理语义，并通过自动化契约检查核对；接口不直接泄露持久化对象的内部字段。兼容策略和文档生成方式由 SPEC 明确。

明确区分“已确认拒绝/回滚”和“受理结果尚不能确认”。受理未确认且仍能返回响应时也使用 `503`，但机器类别与明确满额拒绝不同，并明确要求保留原幂等键找回结果；不能只按 HTTP 状态决定创建新请求。连接中断没有收到响应时也按未确认处理。明确满额拒绝可以在容量释放后按原操作重新申请，未确认请求必须先用原身份恢复。API 返回成功须与业务持久状态一致，外部错误不得被吞掉后包装成完成。

数据库保护业务唯一性、关系和并发更新；任务/待投递、发布/引用/终态、问答结果/终态等关键写入具有明确的一致提交边界。数据库不可用或迁移不兼容时拒绝不安全写入，不能用内存临时状态冒充持久受理。

长时间媒体/模型操作和 SSE 连接不能持续占有业务事务或泄漏数据库连接。连接等资源有上限及释放行为，不能因为慢客户端或任务退出使后续请求无界等待；具体连接管理留给 SPEC。

迁移可在空库执行，并能升级保留配置、正式版本、问答与分享状态的既有样本；失败有诊断和恢复步骤，不自动删除用户数据重建。历史列表和证据读取有分页/规模边界，避免 N+1；在代表性样本上保留执行计划、查询次数和 I/O/延迟证据，按实际开销决定索引与查询调整，不以所有查询必须走索引作为通过条件。

### REQ-12 限流、资源与超时

P0。提供可配置且能实际执行的接单/等待容量、Worker 与媒体处理并发、Provider 共享并发和速率、视频时长、下载字节、工作区占用、图片/上下文规模、模型调用次数及任务/阶段时限。任务总期限从受理开始，覆盖排队、资源等待、处理与自动重试；阶段/调用时限另行约束。初始值随部署和样本验证，不预填性能承诺。

并发上限与单位时间调用配额分别约束，跨 Worker、文章和问答的共享配额不能被各进程独立计数绕过。并发限制针对本实例可控制的发送和处理；本地超时不能证明供应商后台已经停止。任务自动重试不重置总预算；资源等待和取消有明确终止结果。超限、外部进程停滞或磁盘不足时停止相关处理、记录原因并收敛资源占用，不继续积累无界工作。

Redis 作为 Broker、临时协调和 P1 缓存的故障行为分别定义：Broker 中断由持久任务与待投递状态驱动恢复；影响受限调用的协调不可确认时暂停新的受限调用并报告；读取缓存失效按 P1 显式策略回源。Redis 不可用不使已发布内容或已受理任务身份消失。

### REQ-13 结构化日志、状态与健康

P0。日志和执行记录贯通 HTTP 请求、任务、执行尝试、阶段、外部调用及发布，区分排队、资源等待、处理和外部响应耗时。记录错误类别、失败位置和未知用量，能从一次提交定位问题；默认不记录凭据、完整 Prompt、字幕或私人问答内容。

健康检查区分进程存活、服务接单条件及依赖降级。数据库/迁移、Broker、Worker、存储和媒体工具异常可定位，不以 API 进程仍在运行证明任务能执行。Broker 降级时允许范围内的持久接单和已有结果读取，不能声称已经开始执行。健康检查不触发付费模型调用。

基础状态查询和日志随主链交付，P1 概览将已有信息组织为排障页面，不把基础观测延迟到 P1。

### REQ-14 测试、CI 与本地部署

P0。自动化测试覆盖行为、业务边界与已复现缺陷，按需要包含单元、API、真实 PostgreSQL/Redis 集成、独立 Worker、页面交互和端到端测试。SQLite、mock 或 Celery 同进程测试不能作为行锁、投递、租约与进程退出行为的唯一证据。外部服务可用可控 Provider 注入故障；真实视频/AI 联调另外记录，不混称真实模型结果。

CI 至少执行项目类型/静态检查、自动化测试、迁移、真实 PG/Redis 与独立 Worker 的核心业务路径、前端构建；投递、租约和进程退出检查不能只用同进程 Worker 替代。按交付阶段补齐镜像构建与端到端烟测。无真实付费凭据不能成为跳过持久化与故障正确性测试的理由。测试失败不通过削弱断言或跳过用例来消除。

Compose 交付完整前端、API、Worker、调度/恢复所需进程、PostgreSQL、Redis、媒体工具和持久化资源，并提供配置示例、迁移、启动、检查日志、升级与失败恢复说明。用户在自己的机器运行，无需自建云控制面；依赖就绪不能仅靠固定等待时间判断。

容器重启保留配置、任务、正式成果、问答和分享/撤销状态，普通重启按持久记录恢复。密钥不提交，缺失必需解密材料明确失败，不悄悄生成新密钥覆盖旧数据。部署说明给出实际验证过的环境、软件版本与资源条件，不声称尚未测试的平台均受支持。

### REQ-15 配套备份恢复

P1，完整 V1 必验。部署者按文档制作有明确一致性点的配套备份，覆盖数据库、长期文件及解密配置所需密钥材料；记录备份时点、恢复覆盖范围和验证方法。恢复到干净实例后，正式版本、导图、图片、字幕、问答、有效分享和撤销状态与备份点一致，不混用不同批次数据冒充恢复成功。

恢复旧备份不能假定外部供应商也回到备份时点。恢复出的所有未完成任务结束为“恢复中断”的失败，保留备份时状态、已完成阶段与调用账；旧待投递工作和旧执行权不得自动生效。部署者核对恢复点后，按主动重试创建新任务；已完成和 unknown 调用记录继续保留，不能因备份中没有后续记录而断言未发生过调用。该规则用于备份恢复，不替代普通容器重启的自动恢复。备份之后未纳入备份集的数据不承诺恢复。

### REQ-16 内部运行概览

P1，完整 V1 必验。个人入口提供本地服务/依赖健康、排队数量、待投递积压与最老等待、Worker 心跳、磁盘、失败分类、应用/配置版本及阶段耗时、错误计数、已知与未知调用用量等基础运行指标，显示采集时间，允许按必要任务/调用 ID 进入既有排障记录。采集失败显示不可确认，不用零值伪装正常。

概览不公开私人来源 URL、字幕、问答、Prompt、外部正文或凭据，不在分享入口可访问，也不增加账号和复杂权限平台。

### REQ-17 Redis 版本内容缓存实验

P1，完整 V1 必验实验，启用可选。业务对象为反复读取的正式文章版本内容或渲染结果，缓存不保存任务权威状态或授权结论。分享入口每次读取仍检查有效性和版本绑定；图片请求仍检查允许范围与资产状态。

无缓存、冷缓存、热缓存采用相同内容、请求条件与环境，对照延迟、查询次数、命中率、内存和结果一致性。版本变化、分享撤销、资源失效及 Redis 故障不能返回越权内容；未命中/故障按明确策略读取持久源并记录降级，不借回源触发生成。

无可复现净收益时保持关闭，保留实验及取舍记录即可通过；本项目不因 Broker 已使用 Redis 就宣称完成读取缓存实践。缓存实验可以和 REQ-18 使用同一组真实证据，但“无收益关闭”本身不代表完成了所有性能分析工作。

### REQ-18 实测性能与资源优化

P0。真实主链跑通后，根据阶段耗时和资源数据选择至少一个可复现瓶颈，保留改动前后相同样本、配置和环境下的原始结果、波动、功能回归与最终取舍。指标可为队列等待、数据库查询/扫描、取帧或 I/O 时间、内存/磁盘及模型等待，不预设必须优化的组件或提升比例。

实验没有净收益时可以回退改动并解释原因，不能编造 QPS、成功率或延迟，也不能以缓存命中率代替整体收益；外部服务波动与缓存冷/热状态分别记录。仅列出技术组件、截图或理论推断不构成性能验收证据。

## 4. 关键一致性与异常结果

| 情况 | 必须观察到的结果 |
| --- | --- |
| 响应丢失或接单提交结果不确定 | 原操作身份可恢复；同键查询/重发不能形成第二个任务，不用新键掩盖不确定结果 |
| 数据库受理成功、Broker 发送失败 | 原任务可查询并明确等待，恢复后补投，预算和身份不重置 |
| 消息重复、Worker 中断或旧执行者返回 | 阶段结果按有效性复用，旧执行者不能写回，同任务只有唯一正式发布或明确失败 |
| 取消与发布交错 | 以服务端持久结果确认唯一赢家，不能同时显示已取消且新发布成功 |
| 无字幕且未配置 ASR | 原任务失败保留；配置后从原页创建新任务，不自动重启 |
| 外部请求可能已发送且无法确认 | 本地任务失败、结果/用量未知、草稿保留；恢复不重发，主动重试新建关联任务 |
| 写文件、登记、发布或清理时崩溃 | 未完成/孤儿产物可识别；正式引用不被误删，不把缺损结果当作成功 |
| 源媒体已清理或 URL 内容变化 | 原正式成果可读可导出；无法证明同源时拒绝补看新帧，不改旧证据 |
| 新版本生成失败或分享已撤销 | 原正式文章仍可读；旧有效分享仍固定旧版本，已撤销分享的新内容/图片请求被拒绝 |
| Redis 故障或依赖不可确认 | Broker、协调、缓存按各自策略处理；不可确认不伪装正常，已持久化事实不丢失 |
| 从旧备份恢复 | 恢复点、原状态及中断结果可见；所有未完成任务停止自动执行，旧待投递工作和执行权失效，核对后主动新建重试任务 |

## 5. V1 验收标准

完整 V1 须同时满足功能完整性、架构合理性、工程正确性、运行可靠性、可复现与可验证性五个维度，并通过全部 P0 及本草案列出的备份恢复、内部运行概览、版本缓存实验三项 P1。开发切片通过只说明该切片已交付；P2 不阻塞 V1。

每个验收项保存实现版本、环境/依赖版本、前置样本和配置、实际命令或页面/API 操作路径、预期与实际结果、数据库/文件/调用记录及脱敏日志位置。UI 验收实际操作并查看关键状态；受控故障测试与真实媒体/AI 联调分别记录。以下都是待执行要求，不能将表中步骤视为已经运行。

## 7. 排除、后置与待设计边界

不新增完整账号、多租户、支付计费、团队协作、批量/播放列表平台、本地上传、复杂编辑器、通用 Agent Runtime 或多 Agent 平台。不要求微服务、多机高可用、跨地域部署或未经测量的吞吐目标。

没有将原 PRD 已承诺功能移出 V1。ASR、专题模式、追问、导出分享、清理恢复及 P1 的较后切片都是开发顺序安排，不是延期到完整 V1 之后。P2 技术不补充为强制依赖；是否采用须另行说明场景、成本和验收。

现有四份 ADR 全部保留。本文新增的“重新解读重新执行文章生成”“失败问答以新轮次重新提问”和“旧备份恢复将未完成任务标记恢复中断，核对后主动重试”是供本次草案评审的业务细化，不修改 ADR。当前没有因产品范围不清而阻塞草案的架构选型；模型/ASR 的实际可达性、视觉能力和本机资源仍需按真实样本验证。

SPEC 再明确 API DTO、表结构/索引、身份规范化与阶段复用指纹、Redis Key/Celery 配置、执行栅栏/恢复算法、资产提交与清理算法、管理入口鉴权与代理边界、备份一致性实现、部署参数和具体测试命令。本草案不预先规定这些实现。
