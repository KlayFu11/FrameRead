# FrameRead 产品需求文档（PRD）

V3 产品需求于 2026-11-17 正式冻结，覆盖 FrameRead 的用户与媒体管理、链接与字幕、视频处理、四模式 Agent 分析、结构化报告、检索追问、异步恢复、客户端与工程运行。

需求编号为 `R3-01～R3-14`，验收编号为 `A3-01～A3-22`。本文是 FrameRead 唯一正式的产品需求基线。功能是否交付以验收记录为准，实施按独立任务取得授权。接口、数据与运行契约见[全局技术规格](SPEC.md)。

## 1. 产品定位与成功标准

FrameRead 是基于 Java 21、Spring Boot 和 Vue 3 的长视频智能理解与分析 Web 平台。用户把本地视频或可公开获取的视频链接转为可阅读、保存、核对和继续分析的内容，减少在长视频中反复寻找论述、步骤和证据的操作。

四种 Agent 分析模式生成结构化分析结果 `AnalysisResult`，将模式化段落 `Section` 与核心结论、时间证据、分析建议呈现为 Markdown 报告。用户可保存、阅读和导出报告，也可继续追问。

产品成功标准是业务闭环完整、功能与权限边界清楚、数据和任务行为可解释、服务运行可靠、配置与验证可复现。模型自评、组件名称或未经实测的性能数字不构成验收证明。

### 1.1 用户与主要场景

| 角色 | 需要完成的任务 | 权限边界 |
| --- | --- | --- |
| 未登录访问者 | 注册或登录 | 不访问受保护媒体、成果和任务 |
| 登录用户 | 上传或导入视频，选择分析模式，阅读、核对、检索、追问、反馈和导出 | 只操作获授权的媒体、来源文本、结果和图片 |
| 管理员 | 查询和重放失败分析 | 管理入口须通过管理员鉴权 |
| 部署者 | 设定模型与依赖，启动、维护和验证实例 | 通过部署环境管理配置 |

用户可以对课程、技术分享、访谈或本地录屏设置通用、学习、审查或创作目标，阅读结构化报告，点击时间证据核对原片，再检索、连续追问或修订分析计划。报告范围由本次目标和模式决定。

### 2.3 功能边界

产品范围排除独立图文文章生成、文章任务与编辑发布系统、复杂版本管理、公开分享、全片导图、离线图文 ZIP、批量视频及播放列表处理。对话围绕当前视频，选段或选帧问答和永久会话平台超出范围。

分析采用四模式 Agent 和异步协议，范围排除强制再生成开关、任务取消、部分成功状态机、附加语义审核与发布门禁、独立任务运行时、永久事件平台及新增中间件。字幕语言设置、原语检测模型和字幕与 ASR 逐句融合超出范围。完整应用容器化、独立观测后台、备份平台与指定缓存实验属于可选工程范围。

## 3. 完整用户旅程

### 3.1 本地视频

用户登录 → 完成普通上传或分片续传 → 获得自己的媒体记录 → 设置分析目标和模式 → 用 ASR、OCR 和关键帧构建上下文 → 检索证据并分析 → 保存和阅读报告 → 核对时码、追问、反馈、修订计划或导出。

本地视频使用 ASR 取得文本，无需平台来源。媒体管理、独立文字提取和音频下载可分别操作。

### 3.2 视频链接

用户提交单视频链接 → 识别并规范化来源 → 获取并保存媒体和必要元数据 → 构建上下文时验证平台字幕候选 → 采用有效字幕或回退 ASR → 进入与本地上传共用的媒体处理、检索和四模式分析链 → 保存和展示报告 → 核对原片并继续追问。

网页上传或导入成功后进入分析工作区，由用户启动分析。扩展的“提交分析”在导入成功后提交分析请求。媒体保存、分析完成、读取报告与后续对话分别呈现各自的状态。打开已保存报告只读。

### 3.3 前后端协作

| 用户动作 | 系统责任 | 用户可见结果 |
| --- | --- | --- |
| 上传或提交链接 | 鉴权、输入检查、取得并保存媒体及来源 | 能区分导入中、导入成功和失败 |
| 选择模式并启动分析 | 按媒体、目标、具体模式管理身份、限流、异步处理和结果复用 | 能查看排队、处理、完成或失败，AUTO 可看到具体模式 |
| 采用字幕或 ASR | 选择来源、保存原文与时间、报告回退原因 | 能确认使用何种文本，以及已知的来源不足 |
| 阅读和核对 | 按权限读取已保存成果与实际引用资源 | 能阅读、定位原视频，不因刷新自动重新生成 |
| 追问、反馈或修订计划 | 使用当前媒体的固定上下文和 Agent 能力 | 回答与当前媒体相关，区分视频证据、分析和片外补充 |

## 4. 功能需求

### R3-01 身份、会话与数据隔离

系统提供注册、登录、退出、会话与登录保护。所有媒体、来源文本、成果及引用资源按所属用户授权，失败管理与重放须通过管理员鉴权。

合法用户可完成获授权的操作。未登录、其他用户或无管理员权限的访问被明确拒绝。验证见 A3-01、A3-19。

### R3-02 本地上传、续传与媒体管理

系统支持普通上传、分片初始化、传输、状态查询、合并及断点续传，用户可查看、播放和删除自己的媒体。中断、缺片、合并失败及响应丢失时须核对实际结果，避免误报成功或重复完成。

按媒体生命周期保存及删除媒体、分析成果和图片。清理资源时须保护其他媒体仍使用的内容。完成条件见 A3-02、A3-18。

### R3-03 单视频链接与来源识别

用户可提交公开可获取的 Bilibili、YouTube 单视频常见长短链接。Bilibili 处理指定分 P，缺省取第一 P。YouTube 同时含视频和列表参数时只处理指定视频。纯列表、频道、合集或不能确定单视频的输入明确拒绝，不启动批量任务。时间参数仅用于播放定位。

| 必须覆盖的链接形式 | 处理边界 |
| --- | --- |
| Bilibili `/video/BV…`、`/video/av…`，可带 `p` | 对应一个视频分 P，时间和追踪参数不改变该身份 |
| Bilibili `b23.tv` 短链接 | 展开后核对最终单视频身份。超时、循环或最终不是单视频时明确失败 |
| YouTube `/watch?v=…`、`/shorts/…`、`youtu.be/…` | 规范化为同一个视频身份，附带列表参数时限于选定单视频 |
| 纯播放列表、频道、合集 | 拒绝处理并提示提交具体单视频 |
| 其他可下载的公网 HTTP(S) 来源 | 经安全校验后使用通用下载路径，支持范围不限于上述两平台 |

保存原始输入的安全显示值、规范化来源、平台/视频/分 P 身份，以及可取得的标题与时长。未知信息明确标记缺失，同一视频的不同分 P 各自核对来源。

来源不支持、输入不能确定单视频、短链解析失败、可确认的平台限制、媒体下载失败及超时应有稳定可区分的业务错误类别和提示。无法确认具体原因时如实报告。受限内容以平台允许的访问为限。HTTP 状态码、字段及兼容映射见[来源说明与业务错误](SPEC.md#spec-api)。完成条件见 A3-03～A3-06。

### R3-04 平台字幕自动选择

系统自动挑选字幕，按人工、自动、类型未知的顺序处理，同类别按中文、英文、其他语言依次尝试。无法确认字幕类型、语言或是否为译字幕时如实记录。

候选不可用时尝试下一条轨道。用户无需手动选择语言或字幕，单条字幕请求失败时仍可处理视频。完成条件见 A3-07、A3-08。

### R3-05 文本可用性、ASR 回退与时间来源

有效字幕应可解析、非空、与当前视频/分 P 一致，且有可确认的时间信息。损坏、越界或明显截断时尝试下一轨道。无可用字幕时按配置运行 ASR。采用有效字幕时，同一分析目的的自动转写次数为零。独立文字提取仍可单独请求。

保留原始文本、采用来源、语言、类型可确认程度、原始时间区间及采用/回退原因。清洗文本不能覆盖唯一原文，合并上下文不能丢掉原始出处。ASR 只有分片区间时标示区间级精度，不伪造逐句时间。

字幕采用依据可解析、非空、同源及可确认时间等可观察条件，不以时间覆盖率代替语义完整性判断，也不为验证字幕而自动再做同目的 ASR。字幕候选失败及回退原因需要可诊断，但不能改变媒体已成功导入的事实。

ASR 分片失败时记录并跳过相应分片，保留成功部分。没有可用转写时，将空结果或异常交给上下文处理。ASR 或 OCR 单支失败后，由 R3-06、R3-10 决定继续、降级或终止。

报告可使用与原始字幕和 ASR 分片匹配的粗粒度区间，按实际精度标注并说明文本覆盖不足。完成条件见 A3-08～A3-10。

### R3-06 视频上下文、画面与检索

系统以平台字幕或 ASR 作为文本输入，与 OCR、抽取并去重的关键帧及时间信息一起构建视频上下文。本地上传用分段音频转写取得文本。长视频采用分块、片段摘要、Embedding 和混合检索，向量检索失败时可走同源降级。

文本处理与 OCR、关键帧处理并行。一支异常时可使用另一支所得内容。双支失败或无法形成可用上下文时，进入错误处理。OCR 单帧失败或帧资源不可用时按实际可得证据降级。报告只以取得的帧作为图片证据。复杂图表、动态视觉事件、像素理解及逐帧推理超出当前模型和证据范围。

时码反映实际字幕区间、ASR 分片、关键帧或估算精度。网页在保存媒体的播放器中定位。扩展仅在确认当前页对应同一视频和分 P，且能够解析时码时跳转原平台。未展开短链和部分长分钟时码可能无法定位，逐句和精确帧定位取决于实际证据。验证见 A3-11、A3-13、A3-20。

复用上下文、分块、检索结果或报告前，须核对来源、语言、分 P 和实际材料。启动处理时先确认本次来源，再判断是否命中适用结果。打开已保存成果只读，兼容处理须保留历史成果，禁止清空全部缓存。完成条件见 A3-11、A3-14。

### R3-07 四模式、自动路由与 Agent 分析

支持 GENERAL（通用）、LEARNING（学习）、REVIEW（审查）、CREATION（创作），AUTO 按目标确定具体模式。通用模式提供结论、时间证据与建议。其余模式分别覆盖知识点、自测和易错点，逻辑、夸大和遗漏审查，或片段、标题、简介和脚本。目标、实际模式、状态、报告及重新分析保持对应。

Planner、Executor、Critic 使用工具与证据检索，按预算执行并留存轨迹，校验结果结构，根据 Critic 反馈补证、重写或修复计划。达到轮次上限时，Critic 未通过仍可保存带警告的报告。时间、用量或费用预算异常时执行失败。报告质量以实际证据与验收为准。

将 `AnalysisResult` 和模式化 `Section` 转换为 Markdown。完成条件见 A3-12、A3-15、A3-17。

### R3-08 结构化报告、阅读与结果保存

用户可保存、重开和导出按本次目标与模式生成的 Markdown 报告，查看核心结论、时间证据、分析建议及模式化段落。

报告基于真实取得的文字和画面引用，区分视频事实、分析建议、审查判断和创作产物。追问中的片外知识须明确来源。报告是否成功、带警告完成或失败依 R3-07、R3-10 的规则判定。

报告按媒体、目标和模式读取结果 Checkpoint。媒体另存最新 Markdown 摘要。相同作用域的结果可覆盖，计划修订开始执行时重置其相关 Checkpoint。媒体摘要不提供报告版本读取或恢复，编辑、比较、分支及回滚在功能范围之外。

重开报告只读取持久结果，不调用模型。阶段及 Critic 警告随状态或结果返回，Markdown 转换本身不写入 Critic 警告。完成条件见 A3-13、A3-14。

### R3-09 连续追问、反馈与计划修订

用户可围绕当前视频和报告连续追问、检索证据、提交反馈、修改计划或重新分析。对话历史有长度和保留期限制，围绕当前视频提供上下文。

普通反馈用于记录和评估，零新投递。明确提交计划修订后才暂存、投递并重跑。排队期间优先显示排队状态，结果仍持久保存。修订开始时重置该作用域的结果，摘要在有效成果写入时更新。

追问和检索使用本媒体固定材料，包括实际采用的平台字幕。回答区分视频证据与片外补充，证据不足时明确说明，不编造时间出处。完成条件见 A3-15。

### R3-10 进度、失败与恢复

使用 RocketMQ 异步分析、Redis/Redisson 协调以及 Checkpoint 持久化，提供 SSE、状态查询、失败台账和管理员重放。用户可区分媒体导入、排队、处理、完成、警告、失败及恢复。任务独立于页面生命周期，断线或刷新后回查同一作用域。

保存适用的结果 Checkpoint 后，状态可返回完成，包括 Critic 警告完成。有效的计划修订排队期间优先显示排队。结果和媒体最新摘要分步保存。

允许在 R3-05、R3-06 约定的分片或单支失败后继续分析。上下文、模型、结构校验或预算异常按失败类别处理，预算异常结束本次执行，可重试的消费失败有限重投，永久失败按失败机制留证。管理员按权限和有效性要求重放。

重复请求、投递与恢复按媒体、目标、实际模式和来源隔离。有活动工作时返回冲突或相应提示，客户端接续其状态。无活动工作且结果与输入匹配时，普通重发读取该结果。计划修订需显式触发，失败页的重新分析遵循普通提交，更换目标或模式后按新的作用域提交。模型调用受重试和成本估算约束，失败与可能费用可诊断，未确认的费用保留未知。

验证真实依赖下的有限重试、恢复和重放。完成条件见 A3-06、A3-16、A3-17。

### R3-11 导出、扩展与管理

提供分析 Markdown、转写文本和 MP3 导出。浏览器扩展支持登录、当前页或手动链接输入、导入后提交分析、SSE 和时间跳转。配套能力包含失败查询与重放、离线评估、健康检查和工程辅助入口。

后端行为须兼容 Web 和扩展的调用协议。完成条件见 A3-18、A3-20。

### R3-12 API、数据、文件与调用质量

API 须兼容约定的鉴权、错误和响应语义，明确受理、完成、失败及恢复方式。来源写入遵守事务、唯一性和媒体归属约束，实际采用状态和失败可诊断。结果 Checkpoint 与最新摘要的分步保存及完成判据见 R3-10。

引用资源应真实存在并按媒体归属授权，时间、文本及文件来源一致。链接、短链、字幕及其他入口均遵守输入校验、网络和文件访问边界、限流、体积、并发、超时及费用约束。

### R3-13 前端需求与待设计输入

### R3-14 可复现运行、测试与工程证据

使用 Compose 启动中间件，在宿主机运行应用与媒体工具。提供可复现的配置、依赖、启动、持久化、迁移、日志和故障诊断说明。先完成运行环境和自动化测试的可复现验证，再执行实际依赖与端到端验收。

执行必要的单元、接口、集成、真实浏览器交互和故障验证。真实平台、真实依赖、模型联调、固定样本人工核对和受控替身分别留证。禁止通过删除测试、削弱断言或清库消除问题。

主链真实运行后记录耗时和资源基线。优化针对可复现的瓶颈，保留同条件前后原始数据、波动和回归。验收依据实际收益与取舍。完成条件见 A3-19～A3-22。

| 对象 | 业务职责 | 保存与状态边界 |

| 视频来源 | 单视频及分 P 身份、原始及规范 URL、可取得的元数据 | 与实际下载媒体对应，未知信息明确标记缺失 |
| 来源文本 | 实际采用的字幕或 ASR 原文、语言、时间和不足 | 留存必要的原文及原时间出处，与清洗文本分开 |
| 视频上下文与检索材料 | Agent 与交互共用的文本、OCR、帧、分块与证据 | 匹配实际来源后复用，保护已固定材料 |
| 结构化分析结果 | 当前媒体、目标、实际模式对应的 `AnalysisResult` 及报告段落 | 转换为 Markdown 展示与导出 |
| 最新报告摘要 | 媒体保存的最新 Markdown | `media_files.ai_summary` 保存媒体摘要，指定目标和模式的报告从结果 Checkpoint 读取 |
| 目标/模式结果 Checkpoint | 对应目标与模式的结构结果、计划、Critic 及阶段 | 持久保存以供读取和恢复，同作用域可覆盖，修订执行可重置 |
| 对话、轨迹和失败记录 | 追问上下文、诊断与恢复 | 按约定保留期和用途使用 |

来源识别、媒体导入、分析处理和成果可读各有状态。媒体 ID 标识媒体，轨迹 ID 用于诊断。身份、状态、缓存匹配、数据兼容与事务契约见[全局技术规格](SPEC.md)。

普通重复提交、计划修订和读取报告按 R3-08～R3-10 执行。字幕、语言、ASR 来源或分 P 改变实际输入时，须隔离不匹配的上下文、检索与结果，并保留旧报告和可核对的历史数据。失败材料按 Checkpoint 与错误机制管理，记录的费用估算不构成完整调用账。

## 6. 主要异常与预期行为

| 场景 | 应观察到的结果 |
| --- | --- |
| 非法链接、纯列表或短链无法确定单视频 | 明确输入原因，不批量下载、不伪造来源身份 |
| 平台受限、不可达或媒体下载失败 | 报告导入阶段及原因，不把不存在的媒体交给分析 |
| 导入响应丢失或连接中断 | 先从媒体或状态入口核对已保存事实，避免无依据自动重复下载 |
| 单条字幕轨道失败 | 继续尝试其他候选，必要时按配置走 ASR，媒体保存与字幕错误分别判断 |
| ASR 部分分片失败 | 记录并跳过失败分片，保留其余文本供后续分析 |
| ASR 或 OCR 单支失败 | 使用另一支实际得到的材料，按上下文和分析规则决定是否继续 |
| 两支失败或无可用上下文 | 按错误类别处理重试与失败记录 |
| 画面证据有限或只有粗时间 | 如实展示可得 OCR、关键帧和时间精度 |
| Critic 到轮次上限仍未通过 | 可保存并完成带警告的报告 |
| 执行预算异常或模型调用失败 | 按预算、有限重试和失败规则处理，记录实际错误与可确认费用，未确认费用保持未知 |
| 重复请求、重复消息或依赖恢复 | 状态及成果按作用域和来源隔离，阻止重复完成和过时写回 |
| 状态通知断线或刷新 | 回查同一作用域的工作与成果，读取报告零生成 |
| 保存或资源写入失败 | 结果和摘要分步保存并分别处理错误，状态按适用的结果或阶段读取 |
| 越权访问或删除冲突 | 拒绝越权，保护其他媒体的资源，阻止过时执行重新公开已删除媒体的成果 |

## 7. 高层架构与兼容约束

采用 Java 21、Spring Boot、MySQL、MyBatis-Plus/Flyway、Redis/Redisson、RocketMQ、MinIO、Qdrant、LangChain4j、Vue 3 + Vite、FFmpeg/ASR/OCR 和 Docker Compose。依赖版本以工程声明和运行验证为准。

### 7.1 完整系统职责与协作

| 系统模块或组件 | 职责与主要协作 |
| --- | --- |
| Vue 管理与分析界面、浏览器扩展 | 提交输入和目标，选择或路由模式，展示媒体、报告、进度与对话，发起定位和导出 |
| Spring Boot API 与用户服务 | 会话、用户归属、管理员权限、输入和业务错误校验，承接媒体、分析、查询和追问请求 |
| 媒体管理与来源接入 | 上传、分片、续传、单视频身份、URL 下载、元数据与媒体保存，负责列表、播放和删除 |
| 视频处理与 VideoContext | 选用平台字幕或 ASR，结合 OCR、关键帧和时间生成固定上下文，支持分片和单支容错 |
| 长视频与证据检索 | 分块、摘要、向量和关键词/OCR 混合检索，为 Agent 提供相关证据和同源本地降级 |
| Agent 与模型服务 | 运行四模式的 Planner、Executor、Critic、工具检索及预算，支持结构结果、警告、Markdown 转换和追问 |
| RocketMQ 与 Spring 消费者 | 投递、消费、有限重试及失败主题，消费过程协调上下文、Agent 和保存服务 |
| Redis 与 Redisson | 会话、热缓存、活动状态、Pub/Sub 通知、临时对话历史和轨迹、分布式锁协调 |
| MySQL、MyBatis-Plus 与 Flyway | 保存用户、媒体、Checkpoint、失败台账并管理迁移，分别保存最新摘要与目标和模式的结果 |
| MinIO | 保存媒体、分片、原始字幕和帧，支持按权限访问及按生命周期清理 |
| Qdrant 与 Embedding | 支持视频证据向量检索，配合关键词/OCR 与本地检索 |
| 工程运行与管理 | Compose 启动中间件，宿主机运行应用和媒体工具，提供配置、CI、测试、评估、失败重放、健康和日志诊断 |

客户端通过 API 保存媒体和来源后，由异步协调建立视频上下文。检索为四模式 Agent 提供证据，分析结果写入 Checkpoint，最新 Markdown 摘要另行保存。客户端通过状态与 SSE 获取进度和报告。追问复用同一媒体上下文、检索和 Agent。独立文字提取与音频导出通过各自的异步媒体入口。

MySQL Checkpoint 是持久恢复依据，Redis 提供热缓存与协调。SSE 通知配合状态查询恢复，永久事件游标超出范围。持久结果按作用域防止重复提交，外部调用可能因重试而重复，部分故障仍需核对真实结果。

### 7.2 平台来源与上下文边界

导入阶段负责来源识别、下载、媒体与元数据保存。分析阶段从平台字幕或 ASR 选定实际文本，结合 OCR 和关键帧生成同一类型的 VideoContext。上下文、检索与 Agent 使用已确认的材料，用户可核对来源和原始时间。身份、原文、缓存、失败恢复及兼容规则见[来源、固定材料与复用](SPEC.md#spec-source)。
